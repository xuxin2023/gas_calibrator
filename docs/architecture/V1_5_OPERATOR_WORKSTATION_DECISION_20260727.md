# V1.5 操作者工作站产品方向决议

## 结论

面向校准操作者的主产品名称统一为 **V1.5 气体分析仪校准工作站**。它以成熟的
0613 拟合与 0620/0621 开放流通物理流程为校准内核。V1.5 是唯一最终产品；
原 V2 中有价值的分析、报告、证据治理和算法仿真能力迁入 V1.5/共享命名空间，
V2 不再保留产品职责。

## 三层边界

| 层级 | 当前职责 | 不承担的职责 |
| --- | --- | --- |
| V1 | 原生产 GUI 与生产 fallback | 不接入本轮新界面或新功能 |
| V1.5 | 成熟 45 CO₂ 点 + 13 H₂O 湿点队列、0613/0620/0621 校准内核、操作者工作站 | 不复制校准物理逻辑，不默认启用真实 COM |
| V2 | 历史资产迁移区，迁移后退出 | 不再承担产品、校准、UI 或未来版本职责 |

`run_app.py` 保持不变。新的显式启动文件是 `run_v1_5_workstation.py`，当前只允许
V1.5 正式运行器自身的 dry-run 分支。

## 物理与数据合同

1. 生产默认配置锁定为 `legacy_ratio_production`。
2. 成熟点数锁定为 CO₂ 45 点、H₂O 13 个湿点；47/14 属于吸收比候选方案，
   未经真实 acceptance 不得进入生产默认界面。
3. CO₂ 零气锚点与 H₂O 干气锚点是两个不同物理证据角色。H₂O 干气锚点不是
   13 个湿点中的隐含零点，界面明确标为独立证据。
4. 工作站调用现有 CO₂/H₂O queue runner，不重写阀路、温箱、压力、露点、
   稳定性、采样或安全停机逻辑。
5. 证书资料缺少或注册表损坏不阻断软件启动和 dry-run；它仍可阻断最终正式
   证书签发或 release，不得把“可启动”误写成“可正式签发”。

## 当前可验证能力

- 统一入口已对 canonical 队列执行 CO₂ 45 点、H₂O 13 点端到端 dry-run。
- dry-run 证据记录不打开 COM、不控制气路/水路、不写 SENCO 或设备 ID，
  且不构成真实验收。
- V1 默认入口和底层 `CalibrationRunner` 专项回归保持通过。
- 原 V2 parity/smoke 迁入 validation 后继续作为 V1.5 辅助门禁，不改变生产内核。

## 工程审计收口

- `run_app.py`、V1 `CalibrationRunner`、CO₂/H₂O 正式 queue runner 均无本轮差异。
- 全库可收集 5510 项测试；一次全量执行得到 5470 通过、31 失败、9 跳过。
  31 个失败经分类修复后，原失败集合联合复跑 31/31 通过。
- 本轮新增及直接受影响的 V1.5 工作站、中文 i18n、结果/报告口径测试通过；
  simulation suite 的 parity 为 1/1，smoke 为 6/6。
- 原失败并非 45+13 校准内核故障：包含缺失 `matplotlib` 依赖、历史帧审计放错
  V2 core、测试未关闭分析仪腔温等待、页面/工件新增后的旧断言，以及工作台
  `evidence_source` 展示不一致。
- 历史帧审计已移入 V1/V2 adapter 层；工作台模拟证据统一为
  `evidence_source=simulated`。这些调整不修改校准算法和设备控制。

## 未关闭门禁

- P0（发布门禁）：工作站仍只允许 dry-run。真实 GUI 触发、双重解锁、操作者
  确认、no-write 探针、异常安全停机和真实 acceptance 尚未闭环。
- P1（工程效率）：部分 V2 工作台/Tk 治理测试单项耗时 40～100 秒；需要单独
  做测试夹具缓存与隔离，不能借性能优化改动校准内核。
- P1（证书）：证书不阻断启动和 dry-run，但正式签发仍必须完成证书有效期、
  气瓶批次和使用记录审查。
- 验证限制：修复后已复跑原 31 个失败集合及直接影响测试，但没有再次完整执行
  72 分钟的 5510 项全量套件；最终发布前仍需在冻结提交上运行一次全量门禁。

## 代码增长停止规则

下一阶段不再新增另一套校准流程、另一套 runner 或另一套大屏。新增需求必须先
复用现有 V1.5 queue runner、共享存储，并迁移原 V2 中唯一有价值的分析工件；
若确需新增模块，应同时删除或合并等价重复实现。界面只负责配置、状态、确认和
证据呈现，不承载校准物理算法。

## 后续唯一主线

下一阶段先完成 V1.5 产品身份收口和 V2 资产迁移，再在保持当前 UI 调用边界的
前提下完成工作站受控真实执行设计审查。只有双重解锁、操作者确认、no-write
证据、异常安全停机和实机 acceptance 均闭环后，才讨论从界面触发真实队列；
在此之前，真实校准仍使用既有、已审查的 V1.5 正式 queue runner。
