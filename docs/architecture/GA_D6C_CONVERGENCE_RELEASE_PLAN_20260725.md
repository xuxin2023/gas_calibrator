# GA-D6C 项目收敛与有限期发布计划

基线日期：2026-07-25
代码基线：`e81f120b530108c8b49cc86c7ef823314faf1bd5`

## 最终目标

交付一个边界清晰、实现唯一、可审计的气体分析仪自动校准系统：

- V1 继续作为已验证的生产 fallback，不修改 `run_app.py`，不破坏现有流程。
- V2 负责 CO2/H2O 计划、仿真/回放、质量门禁、拟合预览、受控写入治理、报告和证据追溯。
- CO2 零气与 H2O 干气/低水点保持不同的物理锚点。
- 实际温度以箱内铂电阻数字测温仪为准；压力、露点和流量保留真实参考来源。
- 本轮完成条件是 software/simulation release closure；真实 acceptance 只有在另行授权后才执行。

EC 通量闭合、通量协方差和完整涡动相关系统不是本次气体分析仪校准产品的发布范围。已有动态响应研究只保留为可选离线研究能力，不再扩展，也不得阻塞本次收尾。

## 规模基线与判断

当前跟踪的 Python 约 1,694 个文件、644,546 行；V2 源码约 398 个文件、187,305 行。V1.5 辅助工具与验证代码约 390 个文件、108,679 行。该规模已不适合继续按“每阶段新增一套实现”推进。

从 GA-D6C 起执行以下预算：

- 默认冻结新功能；先复用、合并、删除，再考虑新增。
- 每个收敛提交的运行时代码必须净减少；例外必须写明不可复用原因。
- 公共导入路径通过薄兼容壳保留，真实实现只能有一份。
- 不以删除测试换取数字；测试只删除已被等价参数化覆盖的重复项。

## 有限阶段

1. GA-D6C（1 个工作日）：建立规模基线，统一低风险离线文件 I/O，冻结功能扩张。
2. GA-D7（3 个工作日）：按风险排序收敛仓库解析、重复展示和探针辅助函数；每批独立验证、独立回滚。
3. RC 冻结（2 个工作日）：只修 P0/P1，执行完整 regression、nightly、parity、resilience 和中文/UI 门禁。
4. 软件收尾（1 个工作日）：固定版本、清单、哈希、残余风险和操作手册。

软件线目标截止日为 2026-08-07。若届时没有真实设备授权窗口，项目以
`simulation_complete / real_promotion_blocked` 收尾，不因等待真机而无限开放开发。
另行授权后的真实 acceptance 单独安排 1–2 个现场日和 1–2 个报告日，不改变上述软件截止日。

## 每一步的验证合同

每个收敛批次都必须同时满足：

1. 变更前后输出字节或结构等价，定向单元测试通过。
2. 兼容导入对象身份和工件角色不变。
3. regression、nightly、parity、导出韧性通过。
4. `run_app.py`、V1 生产模块、真实 COM、数据库和设备系数均无差异。
5. Ruff、格式、compileall、`git diff --check` 通过。
6. 记录新增/删除行数；若运行时代码未净减少，本批次不进入下一阶段。

## 停止规则

达到以下条件后停止继续加代码：软件套件全绿、P0 为零、P1 有明确责任人和截止日、兼容边界稳定、发布工件可复现。之后的新需求进入下一版本，不再延长本轮 V2 收尾。
