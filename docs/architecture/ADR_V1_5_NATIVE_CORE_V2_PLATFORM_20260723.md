# ADR：V1.5 原生成熟内核与 V2 平台的最终架构边界

日期：2026-07-23

状态：接受，作为发布收口和后续重构的默认决策

## 1. 决策

最终系统采用一个产品平台、两个受隔离算法身份：

1. V1.5 原生成熟 `0613/0620/0621` 路径是当前唯一生产校准内核。
2. 数据库、证据、设备协议、工件、报告等能力进入中性公共层。
3. V2/Web 承担面向用户的平台、分析、治理和未来算法承载能力。
4. V2 新算法继续处于 simulation/replay/shadow/qualification 状态。
5. V2 未完成独立真实验收前，不得替代 V1.5，不得改变默认入口。

这不是长期保留两套重复产品，而是把“已验证的计量内核”和“可演进的平台能力”分开。

## 2. 为什么生产内核选择 V1.5

V1.5 已积累真实运行和问题闭环证据，包括：

- CO2 45 点和 H2O 13 点成熟物理顺序。
- 实际压力、实际露点、分析仪腔温和滤波 ratio。
- 压力优先 SENCO9。
- CO2 零气与 H2O 干气点分离。
- 露点斜率、回弹、ratio 稳定和光学冻结检查。
- 失败点隔离、no-write 评审和受控写后复验。
- 正式 1 Hz 与校准结束恢复 10 Hz 的用途区分。

这些证据比目录结构、代码新旧或 UI 完整度更重要。计量生产内核不能仅因为 V2 看起来更新而替换。

## 3. 为什么不直接删除 V2

V2 中仍有可复用资产：

- Web 产品平台和中文工作台。
- simulation、replay、parity、resilience 和 suite。
- 数据分析、lineage、registry 和工件治理。
- 新吸光度算法的隔离验证能力。
- 未来 EC 动态性能模块的承载位置。

因此可以不保护 V2 当前的内部目录和兼容层，但必须保护经过盘点确认有价值的能力和证据。

允许：

- 移动公共代码到中性命名空间。
- 删除重复 facade、失效入口和未引用适配器。
- 重写 V2 内部模块。
- 将旧 V2 导入保留为短期兼容转发。
- 将不再使用的 V2 代码归档后删除。

禁止：

- 为了整理 V2 而修改 V1.5 成熟物理流程。
- 让 V1.5 正式队列导入 V2 runner、adapter 或 profile。
- 用 V2 新算法的仿真结果覆盖 V1.5 真实放行证据。
- 未经引用审计和替代测试就批量删除 V2。
- 修改 `run_app.py` 默认入口。

## 4. 最终模块结构

### `gas_calibrator.v1_5`

拥有：

- 原生成熟 CO2/H2O 队列与采样
- 物理门禁
- 成熟旧算法拟合
- 正式写前/写后评审
- V1.5 身份和方法合同

不得依赖：

- `gas_calibrator.v2`
- 移植执行路径
- V2 profile

### `gas_calibrator.storage` 和其他公共包

拥有：

- 数据库连接和 SQLAlchemy 模型
- 证据存储
- 通用 lineage、哈希和工件注册
- 通用协议与单位能力

不得拥有：

- V1.5/V2 默认算法选择
- 真实气水路启动
- 系数写入策略

### `gas_calibrator.v2`

近期拥有：

- Web/UI 平台
- simulation/replay/parity/resilience
- 新算法 shadow 和 qualification
- 面向未来的分析服务

V2 的旧存储路径可作为兼容出口，但实际实现归公共层所有。

## 5. V2 代码的处置规则

每个 V2 模块按以下顺序处理：

1. 识别调用者、工件、测试和历史证据。
2. 分类为平台保留、公共层迁移、影子算法保留、兼容转发或历史归档。
3. 为迁移目标补充 parity/contract 测试。
4. 先迁移调用，再保留一个发布周期兼容出口。
5. 引用数量为零且替代测试通过后删除。

不能因为 V2 暂不生产，就把所有 V2 当作无价值代码。

## 6. V2 未来转正条件

只有同时满足以下条件，才讨论 V2 算法替代 V1.5：

- 与 V1.5 的输入、单位、压力、露点和温度口径完全对齐。
- 正式点计划和物理门禁 parity 通过。
- replay/simulation/suite 全部通过。
- 真实设备独立 no-write 验证通过。
- 真实静态 CO2/H2O 验收通过。
- EC 10 Hz 动态延迟、频响、同步和噪声验收通过。
- 不确定度和证据 lineage 完整。
- V1.5 fallback 仍可用。

在此之前，V2 是可重构的平台和候选算法层，不是生产校准内核。

## 7. 当前实施决定

本次先执行：

1. 将数据库连接和 SQLAlchemy 模型从 `v2.storage` 移到 `gas_calibrator.storage`。
2. 将 V1.5 的所有存储依赖改到公共层。
3. 保留 `v2.storage` 兼容出口，确保 V2 测试和已有工具不立即失效。
4. 增加源码隔离测试，阻止 V1.5 再次导入 `v2.storage`。
5. 后续根据治理清单逐项处置 V2，而不是整目录删除。
