# V1.5 全自动校准能力与缺口表（2026-06-17）

## 1. 范围说明

本表基于离线快照：

`logs\v1_5_offline_capability_snapshot_20260617`

本次只验证 V1.5 的离线编排、证据索引、操作台和后处理闭环骨架；没有打开真实 COM、没有控制气路/水路、没有控制 PACE、没有写 SENCO、没有修改设备 ID。因此这里的结论是“自动化能力和缺口梳理”，不是新的真机 acceptance。

## 2. 正式物理流程主干

V1.5 正式校准主干应固定为：

```text
LOAD_PLAN
  -> PRECHECK / ID + GETCO
  -> S5/S6/S7/S8/S9 辅助系数状态确认或受控中性化
  -> 压力通道校准 / SENCO9
  -> 温度通道评审 / SENCO7/SENCO8
  -> CO2 开放流通采样
  -> H2O 开放流通采样
  -> QC / 候选系数拟合
  -> S5/S6 输出层修正评审
  -> 受控写入
  -> 写后复验
  -> 数据库 / 证据包 / 报告 / 证书归档
```

物理原则仍然是：正式 CO2/H2O 主校准基于开放流通、持续刷新、组分稳定和可追溯证据；封路压力点、动态控压探针、PACE continuous sink、VENT-hold 只能作为工程诊断，不默认进入 CO2/H2O 正式拟合。

## 3. 当前能力与缺口

| 阶段 | 当前能力 | 剩余缺口 | 物理意义 | 下一步动作 |
|---|---|---|---|---|
| 计划与溯源 | 可生成 full-flow plan、stage manifest、formal contract 和 run evidence status。 | 真机运行时仍需绑定真实标准气证书、参考设备证书、配置 hash 和操作者信息。 | 校准不是临时读数，必须冻结本次测量方案和输入量来源。 | 在正式 runner 启动前强制导入本次证书和计划快照。 |
| 设备身份与 GETCO 备份 | 已有初始化和 GETCO 证据链设计；操作台可显示预检状态。 | 真机时必须以设备 ID 为身份，不得以 COM 或 GA 序号作为最终身份。 | 串口会漂移，设备 ID 才是被校仪器身份。 | 初始化阶段自动核对 ID、端口映射、GETCO1-9 旧值和 hash。 |
| S5/S6/S7/S8/S9 辅助系数状态 | 已明确 S5/S6 是输出层线性修正，S7/S8 是温度，S9 是压力；后处理执行器已有受控写入占位。 | 真机 run 前需要把旧值完整归档；是否中性化要形成受控证据，不能隐式混入主拟合。 | 辅助系数会影响最终显示层或输入量，若不建模会污染 CO2/H2O 主系数。 | 初始化 runner 将旧值快照写入数据库/证据包，并输出受控中性化或保留建模结论。 |
| 压力通道 / SENCO9 | 已有独立压力校准路线和 no-write/受控写入思路。 | 真实 PACE/COM22 仍需现场执行、复验和归档；微漏气时低压点需降级或剔除。 | P 是 CO2/H2O 内部算法输入量，压力错误不能用组分系数吸收。 | 主校准前先跑压力校准；通过后进入 CO2/H2O。 |
| 温度通道 / SENCO7/SENCO8 | 已有温度异常补救经验和数字测温仪证据使用方案。 | 多温度温箱成本高；单温度修复只能作为工程补救，正式多温度拟合仍需温度证据。 | T 是 CO2/H2O 内部算法输入量；温度系数异常会把温度错误吸收到组分系数。 | 初始化阶段增加温度系数异常评审；异常时先修温度，再跑组分。 |
| CO2 开放流通采样 | 已有专用 open-flow runner、露点门禁、ratio 稳定证据、独立设备判稳思想。 | 真实运行需确认阀门在采样窗口保持打开；所有合格点都应作为拟合候选，不再人为分 fit/verification。 | CO2 主校准要证明分析仪看到的是稳定标准气，而不是残气混合物。 | 下一轮真机统一记录 route_open_at、sample_window_at、route_closed_at。 |
| H2O 开放流通采样 | 已有 HGEN 预热、露点/H2O ratio/dry-gas anchor 证据路线。 | HGEN 不应每点反复停启；水路压力波动不应作为开放流通硬阻断。 | H2O 主校准要证明水汽摩尔分数稳定，且露点仪、温度、压力证据可复核。 | 水路期间保持 HGEN 工作，只切目标点；把压力波动降为诊断项。 |
| 候选系数拟合 | 后处理执行器可生成候选评审、写入包、复验计划和归档缺口清单。 | 仍需把 CO2、H2O、温度、压力、S5/S6 建模合同固定成统一输入数据合同。 | 拟合必须从 raw ratio、T、P 和参考值出发，不能只看最终显示浓度。 | 固化候选系数模型版本、剔除原因和全点参与策略。 |
| 低端锚点 | 已明确 CO2 零气锚点和 H2O 干气锚点不能混为一个概念。 | 需要在拟合数据合同里分别标注 CO2 zero-gas anchor 与 H2O dry-gas anchor。 | CO2 的低端代表 CO2 基线，H2O 的低端代表干气水汽基线，两者物理含义不同。 | 在拟合输入表中增加 `anchor_role`，禁止把两类锚点合并。 |
| 受控写入 | 已有 controlled write package 占位和 no-write 操作台门禁。 | 真机写入必须逐设备 ID 执行，记录旧值、新值、命令、读回、失败处理。 | SENCO 写入改变仪器内部算法，必须可回滚、可审计。 | 受控写入 executor 接入数据库 audit_events 和 write_events。 |
| 写后复验 | 已有复验计划生成能力。 | 复验点、复验环境、S5/S6 是否启用、误差计算口径需自动固化。 | 写入后必须证明最终显示层也符合当前正式范围。 | 写入后自动生成少量 CO2/H2O 独立复验队列。 |
| 数据库 / 证据包 / 报告 / 证书 | 已有 evidence status、archive readiness、operation console、报告/证书生成链路雏形。 | 离线快照显示正式 release 仍 blocked，因为没有真实证据包和数据库闭环。 | ISO/IEC 17025 核心是能证明结果有效、可追溯、可复核。 | 真机运行结束后自动重建 evidence status、入库、生成报告和每台证书。 |

## 4. 当前结论

V1.5 现在已经从“散落工具”整理成了较清晰的受控工具链：

- 离线计划、阶段清单、证据状态、操作台、后处理执行器、闭环 readiness 可以连起来。
- 真实硬件阶段仍不是 one-button live runner ready，而是 `supervised_tool_chain_with_controlled_live_gates`。
- 下一工程里程碑应是：在硬件齐全时，把初始化、压力、温度、CO2、H2O、后处理、写入、复验、归档串成一个可暂停、可恢复、可审计的 live runner。
- 正式 release 之前必须补齐真实证据包，不能用离线 snapshot 代替真实 acceptance。

## 5. 程序边界
