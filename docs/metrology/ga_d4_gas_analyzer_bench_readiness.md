# GA-D4 气体分析仪真实台架协议准备度

## 1. GA-D4 解决什么问题

GA-D3 已经证明综合工作包络的离线计算和异常拒绝能够闭环。进入真实台架前，还必须回答另一类问题：

- 标准气体和参考仪器是否可溯源且在有效期内；
- 试验矩阵是否完整，是否会因顺序漂移形成系统偏差；
- CO2 与 H2O 的稳定、吹扫和恢复判据是否符合各自物理机制；
- 不确定度预算是否覆盖气源、参考仪器、环境、分析仪和记忆效应；
- 原始数据、诊断报告和正式结论之间的工件角色是否清楚；
- 当前是否仅完成协议准备，而没有越权成为真实执行或验收。

GA-D4 对这些条件做 simulation-only、offline、no-write 的准备度检查。

即使所有门禁通过，输出也只能是 `protocol_design_ready=true`。它固定保持：

- `ready_for_real_execution=false`
- `execution_authorization_status=not_requested`
- `real_acceptance_status=blocked`

## 2. 可溯源资产

协议要求八类独立资产角色：

1. CO2 零气标准；
2. CO2 跨度气标准；
3. H2O 干气参考；
4. H2O 湿度参考；
5. 压力参考；
6. 温度参考；
7. 流量参考；
8. 时间基准。

每条资产记录必须包含资产标识、角色、序列号、证书号、校准日期、到期日期、状态、溯源链、标准不确定度和单位。

在锁定的协议日期上必须满足：

- 校准日期不晚于协议日期；
- 协议日期早于到期日期；
- 资产状态为 `active`；
- 证书和溯源链非空；
- 标准不确定度为正的有限值；
- 不确定度单位与资产物理量一致，且不超过该角色的台架准入上限；
- 每个要求角色恰好出现一次。

缺失、重复、过期、证书空缺或不确定度无效都会阻断准备度。

DUT 还必须锁定分析仪标识、型号、序列号、固件版本和软件构建号，防止计划与实际被测对象发生静默替换。

## 3. 试验矩阵和随机化

GA-D4 保留 GA-D3 的完整矩阵：

- 温度：5、25、45 °C；
- 压力：850、1000、1100 hPa；
- 流量：8、12、16 slpm；
- 每个气体 27 个环境格点；
- 4 个浓度目标；
- 升序和降序；
- 起始和结束会话；
- 3 次重复；
- 每个气体计划 1296 行静态测量。

27 个环境格点必须全部出现且只能出现一次。顺序使用记录种子的 `seeded_shuffle`，分析程序会从种子重建顺序并逐项核对。

这样既避免按温度、压力或流量单调执行造成的时间漂移混淆，也保证计划可以重放和审计。仅写一个“已随机化”标记而没有可重现顺序不能通过。

## 4. CO2 与 H2O 的独立物理路径

CO2 通道使用：

- 锚点：`co2_zero_gas`，0 ppm；
- 路径语义：`co2_zero_span_dry_path`。

H2O 通道使用：

- 锚点：`h2o_dry_gas`，0.2 mmol/mol；
- 路径语义：`h2o_dry_wet_conditioned_path`。

H2O 干气点不是 CO2 零气。H2O 路径还必须评价从湿到干的恢复比例和保持时间，用于约束吸附、解吸和管路记忆。任何锚点或路径互换都会失败。

## 5. 稳定、吹扫和恢复判据

两个通道都必须给出：

- 稳定窗口长度；
- 窗口内最大量程归一化斜率；
- 最大量程归一化标准差；
- 最大等待时间；
- 结束后的锚点复核。

H2O 还必须给出：

- 湿到干恢复后的残余比例；
- 恢复保持时间。

判据不能只设置下限或无限等待。超时仍不稳定必须形成失败证据，不能选择性删除该点后继续形成矩形包络。

台架物理控制还必须预先声明并通过泄漏保持、最大压力衰减、最小吹扫体积倍数、H2O 湿润路径材料及温控、共享时间基准和安全排放条件。

## 6. 不确定度预算

CO2 预算至少包含：

- 认证气体标准；
- 气体输送与配气；
- 压力、温度、流量参考；
- 分析仪重复性；
- 漂移与回差；
- 交叉干扰；
- 数字分辨率。

H2O 在此基础上独立包含：

- 湿度参考；
- 干气残余；
- 吸附与记忆。

各标准不确定度按平方和开根号合成，再使用合同覆盖因子计算扩展不确定度。缺少分量、重复命名、非有限值、覆盖因子不一致或扩展不确定度超限都会失败。

这些预算仍是离线台架规划预算，不是正式计量不确定度声明。

## 7. 工件和证据治理

未来真实台架必须区分：

- `execution_rows`：不可变原始测量行；
- `execution_summary`：执行和计划摘要；
- `diagnostic_analysis`：诊断与失败定位；
- `formal_analysis`：只有独立真实验收完成后才允许形成。

当前 GA-D4 输入为 `execution_summary`，报告为 `diagnostic_analysis`。`formal_analysis` 固定为 `blocked_until_real_acceptance`。

## 8. 安全边界

合同和协议同时禁止：

- 真实设备 I/O；
- 自动执行；
- 系数拟合；
- 系数写入；
- 数据库写入；
- 刷新 `real_primary_latest`；
- EC 协谱、涡动协方差或通量闭合。

任何请求字段被改成 `true`，准备度都必须失败。GA-D4 不修改 V1、不修改 `run_app.py`，也不授予 Step 3A 工程探针权限。
